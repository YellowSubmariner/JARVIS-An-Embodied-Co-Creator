# JARVIS 分阶段任务清单

更新日期：2026-11-05

配套阅读：[零基础实施、训练与部署指南](JARVIS_零基础实施训练与部署指南.md)。本清单回答“现在做什么、做到什么程度可以进入下一步”；安装、下载、训练和恢复命令以指南为准。

适用条件：Kinova Gen3 七自由度机械臂、Robotiq 2F-85、Windows 游戏本、固定桌面与相机、约 48 小时云 GPU 总预算。第一版只做单层网格、三色同尺寸积木，以及拼图、备料、回收三个分区。

## 使用方法

- 按工作项认领，不固定分配给 A/B/C/D；同一人可以参与多个模块。
- 每个任务完成后，在该行末尾补上认领人、代码或记录位置、验收人和日期，再把 `[ ]` 改成 `[x]`。不能仅凭“代码写完”勾选涉及真机结果的任务。
- 本清单初始全部未勾选，表示尚未按本清单复核；不表示仓库记载的 Kortex 接入等既有工作没有发生。已有成果可直接复验、补证据，无需重做。
- 不适用的任务写明“不适用及原因”，不要把没有执行的任务勾为完成。采用已有可用 VLA 时，可跳过不需要的微调步骤，但单动作和系统验收仍要做。
- 每阶段的“通过条件”满足后再进入依赖它的真机工作。界面、语言理解和任务管理可使用保存的图像、模拟执行结果提前开发，模拟结果要明确标记。
- 全项目先按约 2 至 4 周安排，依据设备时段与进展调整。48 小时是 GPU 预算，不是整个项目工期，也不是必须连续租用两天。

任务记录示例：`认领：姓名；证据：代码提交 / 日志 / 视频位置；验收：姓名；日期：YYYY-MM-DD`。这里不预填人员姓名或完成日期。

## 阶段总览

| 阶段 | 主要目标 | 依赖 | 云 GPU 安排 |
| --- | --- | --- | --- |
| [P0 条件盘点与范围确定](#p0-条件盘点与范围确定) | 知道有什么、先做什么、在哪里运行 | 无 | 不租 |
| [P1 设备与单步接口](#p1-设备与单步接口) | 相机、机器人、停止与最小任务管理可用 | P0 | 通常不租 |
| [P2 数据与软件准备](#p2-数据与软件准备) | 得到可训练的数据，软件流程能预联调 | P1 的相关接口 | 通常不租 |
| [P3 第一次短租试跑](#p3-第一次短租试跑) | 用小任务验证训练、保存、重载和部署可行性 | P2 数据检查通过 | 第一次额度，最多约 4 小时 |
| [P4 训练与单动作真机闭环](#p4-训练与单动作真机闭环) | 得到可重复完成一次取放的 VLA 闭环 | P3 或已复现的可用策略 | 第二次额度最多约 24 小时；部署使用第三次共享额度 |
| [P5 多步编辑与记忆](#p5-多步编辑与记忆) | 多块换色、保护区、预览与暂停续接 | P4 真机能力通过 | 本地推理优先 |
| [P6 人工协作与异常恢复](#p6-人工协作与异常恢复) | 保留人工修改，完成至少一种真实恢复 | P5 | 必要补训与 P4 共用第三次额度 |
| [P7 验收与交付](#p7-验收与交付) | 独立测试、完整存档、重启复现和答辩 | P6 | 按需使用剩余机时，保留备份时间 |

主路径：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7`。遇到失败，回到对应的设备、数据或模型环节修复，不必把整个项目从头再做一遍。

这里的 P0–P7 是工程实施编号，与 [Background](Background.md) 的五个能力阶段分开：原阶段一“单动作闭环”在 P4 验收；原阶段二在 P5 验收；原阶段三在 P6–P7 验收；原阶段四“微调改进”按需要提前到 P3–P4，后续可继续迭代；原阶段五“仿真与研究扩展”放在本文末尾的可选清单。

## P0 条件盘点与范围确定

**目标：** 先明确现场条件、第一条任务和推理去向，再投入开发与租卡。

**进入条件：** 团队能够查阅现有仓库，并安排一次现场设备盘点。

- [ ] **P0-01** 共同阅读 README、实施指南、原始任务要求及 Kortex 维护记录；记录哪些已有成果可以直接复用。
- [ ] **P0-02** 查清游戏本的显卡型号、显存、内存、剩余磁盘和 Windows 版本，保存 `nvidia-smi` 输出或设备信息。
- [ ] **P0-03** 找回此前成功运行 VLA 的代码、模型名称、权重位置、启动命令、动作定义和运行记录；明确能否复现。
- [ ] **P0-04** 与现场负责人确认机械臂当前状态、定位和停止功能；对 J2/J3 的历史问题记录当前结论，不把旧角度登记当作日常初始化。
- [ ] **P0-05** 固定第一条任务为一种短取放，例如从备料区取红块放到指定空格；写清初始布局、结束状态和成功条件。
- [ ] **P0-06** 画出网格和三个分区，选定积木、相机位置与照明；规划两种初始图案和屋顶、窗户等语义区域。
- [ ] **P0-07** 确定先复用既有 VLA，还是验证 SmolVLA；第一轮只维护一条主要模型路线。
- [ ] **P0-08** 确定训练后优先在游戏本推理，并列出本地推理不满足要求时的备用机器或限时云推理方案。
- [ ] **P0-09** 约定设备使用时段、数据保存位置、备份位置和 48 小时机时记录方式；把 P1、P2 任务按当前时间认领。

**交付物：** 设备与环境清单、现有 VLA 复现记录、第一条任务说明、桌面分区图、设备排期。

**通过条件：** 能说明“用哪台机器、做哪一个短任务、用哪条模型路线、训练后在哪里推理”。硬件状态不确定时，继续只读检查与软件开发，暂不进入动作采集或正式租卡。

**对应指南：** 第 1–5 节。

## P1 设备与单步接口

**目标：** 让观察、控制、停止、执行反馈与最小任务状态彼此连通。本阶段验证基础接口，不要求未经训练的 VLA 已经会抓放。

**进入条件：** P0 范围明确，现场负责人允许进行相应动作试验。

- [ ] **P1-01** 复验现有 Kortex Windows 环境：能登录、读设备信息、读关节与夹爪状态，并保存只读检查记录。
- [ ] **P1-02** 在指导下验证有限动作、夹爪开闭、停止和状态回读；记录实际可用的控制方式。
- [ ] **P1-03** 验收全局与腕部相机的实际画面、重连和截图；明确本轮模型究竟使用哪些视角，正式采集后保持一致。
- [ ] **P1-04** 固定相机、桌面和网格，完成适用于当前平面的坐标映射；另行核对夹爪、积木高度与机械臂可达范围。
- [ ] **P1-05** 实现机器人桥接接口，至少能连接、读状态、接收一种明确动作、停止、查询执行状态和返回错误。
- [ ] **P1-06** 写定动作契约：关节顺序、单位、绝对值或增量、坐标系、夹爪方向、频率、时序、限位和角度跨界处理；记录版本号。
- [ ] **P1-07** 实现相机帧与机器人状态的时间戳、有效性和陈旧数据检查，确认没有视角交换或颜色通道混淆。
- [ ] **P1-08** 实现最小 Harness：待确认、执行中、核验中、成功、暂停、结果未知；为每个请求分配唯一编号。
- [ ] **P1-09** 用已验证的基础抓放接口完成一次短任务，保留图像、控制请求、反馈和实物结果；如未使用 VLA，明确标为基础控制联调。
- [ ] **P1-10** 验证暂停、超时和子任务取消会处理未执行动作；控制结果未知时先查询与观察，不盲目重复发动作。

**交付物：** 可调用的控制与相机接口、动作契约、标定与现场检查记录、最小状态机、一次完整联调记录。

**通过条件：** 能解释每一维动作的物理含义，现场动作与反馈相符，停止功能有效；积木未到位时系统不会误报成功。重复定位不可靠、图像错位或动作语义不清时，先修接口，不批量采集。

**可并行：** 文字指令结构、界面、日志、保护规则与模拟执行器均可提前开发。

**对应指南：** 第 5–7 节及附录 B。

## P2 数据与软件准备

**目标：** 得到可检查、可训练的短任务示范，同时让语言与任务管理流程跑通。

**进入条件：** P1 中采集所需的相机、控制、状态和时间对齐已验收。若某个视角不稳定，应先调整并冻结方案，不在录制中途随意替换。

### 示范与数据

- [ ] **P2-01** 确定可重复使用的示教方法：现有遥操作、手柄或已验证的抓放程序；能记录实际下发的动作目标，而不只录视频。
- [ ] **P2-02** 实现 episode 录制，保存图像、实测状态、动作目标、任务文字、时间戳、初末状态、成功与人工介入标记。
- [ ] **P2-03** 先录 5–10 条试验示范，逐条回放并检查图像、夹爪、状态与动作是否对应；剔除或修复错位数据。
- [ ] **P2-04** 准备窄任务首轮数据，可先以约 60 条有效示范为起点；在少数位置变化上重复采集，不把每条都做成不同的新任务。
- [ ] **P2-05** 规划后续放置与回收两类技能的数据覆盖；三色、位置与任务不能形成明显的固定搭配。扩展总量可参考约 150–300 条，再按失败补采。
- [ ] **P2-06** 统一短任务文本与视觉目标表达；确认网格名称如何对应可感知目标，训练与部署采用同一套表达。
- [ ] **P2-07** 保存原始数据及其备份，记录采集程序、相机配置、动作契约和标定版本。
- [ ] **P2-08** 按完整 episode 或采集批次划分 train、val、test，记录固定清单；封存测试数据，不随机打散相邻帧。
- [ ] **P2-09** 用锁定版本工具转换三个独立数据集；检查随机样本和一个 batch，确认维度、字段、任务和图像正确。
- [ ] **P2-10** 确认训练归一化统计量只来自训练集；失败和人工接管片段已分类，没有无标注混进成功示范。

上述数量是试验起点，不是成功保证。先完成窄任务学习验证，再决定扩大数据；不要求第一轮租卡前就采满 300 条。

### 软件预联调

- [ ] **P2-11** 实现文字到结构化编辑请求，至少支持移动与换色；检查格式、对象存在性、位置合法性和歧义。
- [ ] **P2-12** 实现三色、编号、网格和占用状态输出，区分“已确认”与“不确定”，在界面叠加展示。
- [ ] **P2-13** 用模拟执行器跑通任务输入、预览、确认、执行状态、核验和日志；至少覆盖抓空、目标占用与保护冲突。
- [ ] **P2-14** 事先准备独立测试指令与真机初始布局，写明要记录的指标和通过门槛，避免训练完才挑容易的题。
- [ ] **P2-15** 准备锁定版本的训练环境、权重下载地址、磁盘目录、备份方法；优先在游戏本做模型推理预检查，不能运行时明确把可行性检查放进 P3。

**交付物：** 录制器、转换器、经过回放的示范、数据切分清单、任务与视觉接口、模拟闭环、独立测试草案。

**通过条件：** 能完整回放示范并读出正确训练样本；动作定义已冻结；软件能明确处理失败；后续推理地点有可验证的方案。只有 MP4、没有动作标签，或状态被直接复制为动作时，不进入正式训练。

**对应指南：** 第 6、8–10、16 节及附录 A。

## P3 第一次短租试跑

**目标：** 用一小段租卡时间验证整条训练与存档流程，尽早发现会阻塞后续工作的环境或数据问题。

**进入条件：** P2 的窄任务数据、动作契约和数据读取检查通过。使用已有可用策略且本轮无需训练时，记录理由，保留加载、推理与部署检查。

**GPU：** 第一次额度最多约 4 小时，计入全项目 48 小时。4 小时未通过不自动延长；保存记录、停机，回到相应环节修复。

- [ ] **P3-01** 核对租赁实例的显卡、驱动、磁盘保留方式和计费规则，建立机时记录；确认不是误选多卡实例。
- [ ] **P3-02** 按指南安装锁定代码与依赖，确认 PyTorch 能识别 GPU；保存环境和代码版本。
- [ ] **P3-03** 下载基础权重及 backbone、分词器等资源，按指南统一到固定本地资源路径。
- [ ] **P3-04** 上传完整训练数据树，核对文件数量或校验和，再随机读取样本。
- [ ] **P3-05** 从小 batch 开始执行约 200 步试跑；检查输入输出维度、有限 loss、显存和稳定后的单步耗时。
- [ ] **P3-06** 检查保存结果，重新加载一个完整 checkpoint；使用录制观察进行离线推理，核对动作形状、反归一化和单位。
- [ ] **P3-07** 用实际视角和模型配置测试游戏本加载及完整动作块推理延迟；暂不向机械臂发送模型动作。
- [ ] **P3-08** 若游戏本无法满足要求，记录具体原因并验证备用推理路径，确认其费用和租期结束后的可用性。
- [ ] **P3-09** 备份代码版本、数据清单、日志、试跑检查点及训练状态；在另一位置检查存档可读，完成后停机。

**交付物：** 环境记录、试跑日志、可重新加载的 checkpoint、单步速度与显存记录、游戏本或备用机推理测试结果、已用机时。

**通过条件：** 训练能运行并正确保存，重载后仍能解释输出，推理部署路径有实际测试依据。200 步只用于排错，不计作机械臂动作能力验收。

**对应指南：** 第 10–13 节。

## P4 训练与单动作真机闭环

**目标：** 得到一条可重复的真实闭环：明确指令 → 观察与确认 → VLA 取放 → 新观察 → 核验成功或失败。

**进入条件：** P3 通过；或已有策略及适配程序已完成同等加载、输出与部署检查。必须继续使用 P1 的动作契约和停止机制。

**GPU：** 正式训练使用第二次额度，最多约 24 小时；部署、真机对比或必要短训使用第三次共享额度，不另加一笔 12 小时。

- [ ] **P4-01** 固定首轮训练数据、初始权重、输入输出特征和参数，记录实验名称；依据 P3 实测速率确定能在预算内完成的训练长度。
- [ ] **P4-02** 执行正式微调，定期保存检查点；不要仅为了达到某个步数把评估和备份时间用完。
- [ ] **P4-03** 使用独立验证集和训练时的处理器比较候选版本，检查预测动作；最终测试集不用于反复挑模型。
- [ ] **P4-04** 准备完整部署包，包含策略、配置、处理器、统计量、所需资源、适配代码与环境记录；保留续训状态。
- [ ] **P4-05** 在游戏本或已验证的备用机加载部署副本，修正机器路径；测试断网重启加载、峰值显存与端到端延迟。
- [ ] **P4-06** 接实时相机与机械臂状态，仅记录预测、不发送动作；检查时序、范围、夹爪方向和过期响应。
- [ ] **P4-07** 在现场指导下启用限定任务与短执行窗口；验证实际控制节奏、停止、超时和旧动作队列清理。
- [ ] **P4-08** 接入最小 Harness 和视觉核验：控制结束不自动记为成功，未到位和观察不清分别记录。
- [ ] **P4-09** 在预先记录的多个起始条件下重复测试，保留所有尝试和失败原因，达到 P2 预先约定的单动作门槛。
- [ ] **P4-10** 对失败先检查硬件、时序、单位、坐标、相机和控制适配；确属数据覆盖不足时再补采、重训和验证。
- [ ] **P4-11** 冻结一个已验收的动作版本，保存可回滚的代码与权重；更新支持的子任务、起始条件和已知限制。

**交付物：** 可部署模型、单动作程序、重复试次记录与录像、能力范围说明、可恢复存档。

**通过条件：** 在约定条件下完成可重复的 VLA 真机取放，失败不会误报完成，停止和反馈可用。只会输出数组、训练 loss 下降或传统抓放成功，都不能替代本阶段的 VLA 验收。

如果基础模型还不能安全执行，不为凑“微调前后对比”强行上机；先建立经适配的可用基线，准确记录比较的是哪些版本。

**对应指南：** 第 7、12–13、16 节。

## P5 多步编辑与记忆

**目标：** 完成“屋顶三块换成蓝色，窗户保持不变”，并在暂停后正确接续。

**进入条件：** P4 的相关原子任务已验收。若只学会放置、尚未学会回收，先补齐回收能力，不能只靠调度程序拼出尚不存在的动作技能。

- [ ] **P5-01** 建立可查询场景表，记录物体编号、颜色、格子、占用、观察时间与场景版本；相同颜色的物体可区分。
- [ ] **P5-02** 建立目标、保护约束、确认计划、已核验步骤、进行中请求和事件记录，先用简单文件或 SQLite 保存。
- [ ] **P5-03** 实现 ScenePatch：比较当前与目标布局，只列出必要编辑；明确旧块回收、新块放置和等待位的顺序。
- [ ] **P5-04** 在场景副本中逐步检查目标占用、材料数量和保护冲突；将预测状态与实际观察分开保存。
- [ ] **P5-05** 展示待改变与受保护的位置，提供真实的确认、取消和保护标记调整入口；确认绑定具体计划版本。
- [ ] **P5-06** Harness 每次只提交一个已支持的当前子任务，每步重新观察并核验，通过后才更新进度。
- [ ] **P5-07** 实现动作边界暂停：处理旧动作、记录进行中状态，恢复前重新观察并检查旧计划前提。
- [ ] **P5-08** 验证恢复不重复已完成步骤，不跳过未确认步骤，不沿用已失效的位置；先限定同一程序运行期间的暂停续接。
- [ ] **P5-09** 在两种初始图案上完成移动和换色，检查界面进度与真实结果一致，窗户等保护区没有误改。

**交付物：** 多步任务状态与记忆、ScenePatch、预览确认界面、暂停续接演示、完整步骤日志。

**通过条件：** 能完成实际的多步局部修改，保留非目标区域；暂停后凭最新场景接续。逻辑预览通过不等于运动轨迹无碰撞，执行端仍需落实已验证的运动边界。

**GPU：** 使用已部署模型推理，界面、规划和记忆开发不占云训练时长。

**对应指南：** 第 3、6、13、16 节及附录 B。

## P6 人工协作与异常恢复

**目标：** 人可以参与设计，系统记住并保护人的修改；面对一种已定义的异常，能够根据新观察继续任务。

**进入条件：** P5 通过，人工操作与机器人动作可以明确轮流进行。

- [ ] **P6-01** 明确进入人工回合的条件：机械臂已停止、剩余动作已处理、界面提示允许操作；语音暂停不替代独立停止手段。
- [ ] **P6-02** 比较人工操作前后场景，记录可靠变化、涉及对象与时间；无法确定变化时返回不确定并澄清。
- [ ] **P6-03** 根据可靠人工变化生成保护标记并展示，允许用户调整或解除；模型不能自行取消保护。
- [ ] **P6-04** 支持“刚才移动的那块”“保留我调整的窗户”等上下文指令；身份或指代不明时高亮候选并询问。
- [ ] **P6-05** 加入基本语音输入与反馈，保留文字或按键入口；完成播报必须来自真实核验结果。
- [ ] **P6-06** 验证至少一种恢复：合法暂停时移动待取积木到另一已标定位置，恢复后发现旧位置失效，重新观察、规划、执行并核验。
- [ ] **P6-07** 验证新观察使旧计划或旧预测失效时，尚未执行的动作不会继续被发送。
- [ ] **P6-08** 为重试次数和任务耗时设限；缺料、保护冲突、反复失败和观察不清时，明确暂停或请求接管。
- [ ] **P6-09** 记录异常检测、恢复决策、执行结果与人工介入；新方案超出原确认范围时重新展示和确认。
- [ ] **P6-10** 如失败暴露动作技能缺口，按失败类型补采并短训，再重复 P4 相关验收，不直接替换已冻结的可用版本。

**交付物：** 人工修改记录、保护与澄清界面、语音入口、一种真实恢复的完整录像与日志、失败退出规则。

**通过条件：** 人工设计被正确保存和保护，至少一种异常实际完成了恢复，已有成果不被重复或破坏。“所有失败都停机”可作为早期保护措施，但不计作本阶段恢复能力完成。

**GPU：** 仅必要补训使用第三次共享额度；与 P4 的部署和测试合计最多约 12 小时。

**对应指南：** 第 3、13–14、16 节及附录 B。

## P7 验收与交付

**目标：** 证明系统在独立任务上能工作，并让团队另一人可以按文档重新启动。

**进入条件：** P6 通过，待测模型、代码、场景和判定规则已冻结。未完成能力可以列为限制，但不能按完整 JARVIS 能力验收。

- [ ] **P7-01** 整理不少于 20 条独立测试指令，覆盖移动、替换、保护、目标缺失和含糊表达，与提示词示例分开。
- [ ] **P7-02** 完成不少于 10 次真机局部编辑测试，覆盖两种初始图案，保留每一次尝试而非只保留成功录像。
- [ ] **P7-03** 分别报告解析正确率、实际编辑成功率、非目标区域误改，并记录重试、额外搬运、人工介入和耗时。
- [ ] **P7-04** 对每次失败区分语言理解、场景识别、指令校验、动作执行和核验问题；结果未知单独记录。
- [ ] **P7-05** 对完整动作任务，检查目标达成且保护区未误改；对缺料、冲突和歧义任务，按事先约定判断暂停或澄清是否正确。
- [ ] **P7-06** 在可比条件下完成课程方案中的编辑策略比较：整体重排、差分局部编辑、加入人工保护的局部编辑；各组保留必要停止与保护边界，记录额外搬运、非目标变化和用户纠正。
- [ ] **P7-07** 如报告 VLA 微调改善，固定 Harness、视觉和测试条件；如报告记忆或恢复改善，固定 VLA 与外部验收方式。样本不足时注明探索性质。
- [ ] **P7-08** 保存最终模型、处理器、统计量、所需资源、适配代码、环境锁、数据清单和结果；续训状态另行保留，复制实际检查点目录而不只复制 `last` 符号链接。
- [ ] **P7-09** 由没有负责安装的成员按部署文档从关闭状态重新启动，加载模型并完成一个限定任务；记录缺失步骤并补文档。
- [ ] **P7-10** 完成连续演示排练，确认真实环境、预览、动作进度和核验结果可见；保留清楚标注能力范围的备用方案。
- [ ] **P7-11** 发布代码与启动说明、硬件连接与动作定义、测试结果、失败案例和演示视频位置；明确已完成与待完成能力。
- [ ] **P7-12** 在退租前下载并核对完整存档，至少保留两份；确认租赁实例是否真正停止计费，记录最终已用机时。

**交付物：** 可复现的部署说明、最终可用版本、独立测试记录与报告、失败案例、连续演示、完整备份。

**通过条件：** 另一位成员可按说明重启系统；测试数量、目标及保护要求有证据支持；成果在退租后仍可访问。20 条指令和 10 次真机测试是最低数量，不是性能合格线，也不足以自动支撑所有研究比较。

**对应指南：** 第 13、16–18 节。

## 可选扩展

以下不阻塞 P0–P7，不默认占用已经安排的 48 小时预算；只在核心能力通过后选择一个明确问题推进。

- [ ] **E-01** 在固定系统条件下扩大独立测试与重复试次，进一步比较模型、记忆或恢复机制。
- [ ] **E-02** 围绕一个具体问题建立物理仿真，例如位置变化下的抓放；验证机器人、关节、控制与相机配置。
- [ ] **E-03** 选至少一组对应条件进行真机对照，分别记录仿真与真机结果，不用仿真成功替代真机验收。
- [ ] **E-04** 只有实际完成策略训练与真机迁移验证后，才将结果写为 Sim-to-Real；不把 PPO 或从零训练列为默认任务。
- [ ] **E-05** 如需评估另一种 VLA，先明确当前路线的具体不足，再独立建立可比较的环境、适配与数据转换。

## GPU 预算与停止条件

| 额度 | 共用阶段与用途 | 计划上限 | 实际已用 |
| --- | --- | --- | --- |
| 第一次 | P3 环境、下载、200 步试跑和重载 | 4 小时 | 待填写 |
| 第二次 | P4 正式训练和验证 | 24 小时 | 待填写 |
| 第三次 | P4 部署与对比、P6 必要补训 | 12 小时 | 待填写 |
| 机动 | 各阶段故障处理、最终验证、演示与备份 | 8 小时 | 待填写 |
| 合计 | 全项目共用，不随阶段或重训次数重置 | 48 小时 | 待填写 |

记录实际计费时间，不只记录训练脚本运行时间。若使用多张卡或多个实例，应同时记录实例数和费用，不能把并行租用当成免费缩短时间。分次租用之间先停 GPU，再做不需要 GPU 的补采和开发；剩余额度不必用完。

遇到以下情况先停止当前动作或训练环节，保存证据后回到相应阶段：

- 设备定位、停止或控制反馈不可靠：回 P0–P1。
- 图像与动作错位、单位或动作含义不一致：回 P1–P2。
- 训练不能正常保存或模型重载失败：停长训练，回 P3。
- 游戏本及备用推理位置均未验证：暂不投入主要训练额度，先解决部署可行性。
- loss 下降但真机动作失败：先定位原因，再决定补采或修改参数，不默认继续延长训练。
- 临近机时上限仍在调试：先完整备份，保留已验收版本，调整范围或另行安排资源。
