## 每份文档只负责一类问题

- **仓库 README**：项目入口、当前技术路线、已知条件和导航。
- **Background**：项目动机、架构、能力阶段与实验设计，不复制训练命令。
- **赛博造物背景叙事**：开题报告的科幻愿景、个人创造力与人文价值叙事；技术实现与验收状态以项目方案和任务清单为准。
- **开题报告叙事与结构建议**：围绕“赛博造物”统一背景、目标与创新点，并衔接技术、分工、预算和展示；作为报告写作建议，保留现有项目安排。
- **实施总览**：开发顺序、模块接口、并行安排、GPU 总预算和课程交付。
- **π0.5 专题**：数据与动作契约、采集、标签、格式转换、资源、版本、训练和部署，是本轮技术操作入口。
- **任务清单**：编号、认领、通过条件与证据；勾选不替代测试记录。
- **Kortex 指南**：设备环境及历史操作事实。历史标定步骤不是每次开机的默认操作。
- **原始任务要求**：保留课程需求依据，不加入模型选型或项目包装。
- **Word**：保留历史参考；不承担当前参数、命令或状态的维护。

## 当前状态与历史版本

选择 π0.5 是团队当前实验路线，不表示它已在这台 Kinova 上完成训练或推理。已有控制或遥操作可取放属于团队报告，仍要检查程序并接入日志。相机监看、同步录制、VLA 推理和真机任务成功是不同验收项。

旧指南曾以 SmolVLA 为首选；完整版本可查看 [2026-11-05 提交中的实施指南](https://github.com/YellowSubmariner/JARVIS-An-Embodied-Co-Creator/blob/47ba6021e7e5f000aaf2da2c531426b00ab75717/docs/JARVIS_零基础实施训练与部署指南.md)。历史保留在 Git 中，不另复制多份容易被误用的现行文档。

## 更新规则

1. 选型、设备或接口变化时，更新对应专题与 README 的当前结论；改变架构时同步 Background，改变任务依赖时同步清单。
2. 修改训练命令只维护 π0.5 专题，其余文档引用它。记录核验日期、代码与权重版本，区分已实测、源码核验和待验证。
3. 真实进展在任务清单补负责人、证据位置、验收人与日期。没有证据，不把计划改写为完成。
4. 保留原始数据和模型资源的版本与存放说明；大模型权重、原始视频和私密连接信息不直接放进文档仓库。
5. 重命名或移动文档时检查相对链接；本次整理保留既有路径，Word 与课程原文保持原位。
