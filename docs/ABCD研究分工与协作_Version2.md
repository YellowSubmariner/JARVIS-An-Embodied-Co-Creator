# Project JARVIS：ABCD 研究分工与协作 · Version 2

> 更新日期：2026-10-29
> 本版依据：团队最新确定的“VLA＋Harness”路线与五阶段计划。
> 本版是分工方案的第二版；文中的第一至第五阶段是项目推进阶段，两者不混用。

## 一、共同目标：让 VLA 能被组织起来完成连续任务

我们利用老师提供的 **Franka Research 3**，构建能够与人共同修改桌面积木作品的具身智能体。

典型任务：“把屋顶的三块积木换成蓝色，窗户保持不变。”系统需要完成多次抓放，记住进度，保留人的修改，并在有限异常发生后继续任务。

核心分工是：

- **VLA 负责具体行动：** 根据当前图像、机器人状态与当前子任务生成动作。
- **Harness 负责持续管理：** 管理目标、记忆和进度，组织结果核验，并决定继续、调整、重试或求助。

Harness 从第一阶段就加入。它可以由普通程序、任务状态机、结构化记忆、视觉检查和必要的 LLM 决策组成，不要求训练一个新的管理模型。

我们要验证的问题是：**在相同 VLA 下，加入任务记忆与核验恢复，能否改善多步编辑、人工干预和任务中断后的表现？**

### 相比第一版的主要变化

| 方面 | Version 2 的定位 |
| --- | --- |
| VLA | 从可选拓展调整为核心执行路线，需要尽早验证真机适配 |
| Harness | 从第一阶段开始，逐步增加任务记忆、接续与恢复 |
| B 的视觉工作 | 同时承担环境观察与执行结果证据，不只是为抓取提供位置 |
| C 的工作 | 主责 Harness，组织任务、Memory、规划和恢复 |
| 微调与仿真 | 微调用于改善动作能力；仿真按需要引入，不是基础闭环的前置条件 |

第一版仍限定为固定相机、单层网格、三色积木、拼图区／备料区／回收区，以及预先标注的屋顶、窗户等区域。

## 二、四人职责总览

| 成员 | 主责模块 | 核心问题 | 主要交付 |
| --- | --- | --- | --- |
| A | 语言理解与人机交互 | 用户想做什么？如何澄清和反馈？ | 明确的任务要求、预览确认、交互界面 |
| B | 视觉感知与结果检查 | 桌面现在怎样？执行后真的改变了吗？ | 图像与场景状态、变化检测、核验证据 |
| C | Harness、Memory 与任务管理 | 做到哪一步？下一步怎么安排？失败后如何继续？ | 任务管理、结构化记忆、局部规划与恢复调度 |
| D | VLA 与机械臂执行 | 当前子任务怎样在真实设备上完成？ | 可调用的 VLA 执行能力、设备适配、训练与执行反馈 |

**C 主责管理流程，D 主责动作能力。全局联调由四人共同完成。**

## 三、A：语言理解与人机交互

**研究对象：用户表达、任务意图、上下文指代和交互反馈。**

| 调研技术 | 在本项目中研究什么 |
| --- | --- |
| LLM、提示词与结构化输出 | 提取目标、对象、位置、颜色和保护要求 |
| 多轮对话与上下文理解 | 结合 C 的历史理解“刚才那块”，不明确时追问 |
| 语音识别与语音合成 | 在文字流程基础上增加基本语音交互 |
| VLM，多模态交互 | 与 B 研究结合图像理解“这个”“那块”，按需要采用 |
| VLA 的语言指令形式 | 与 C、D 确认所选 VLA 能接受怎样的子任务表达 |

主要负责：

- 将用户原话转换为明确任务，交给 C。
- 展示 B 的识别画面、C 的修改预览与任务进度。
- 接收确认、取消、暂停和解除保护等真实用户操作。
- 根据 C 的核验结论反馈结果，不能仅凭动作已发出就播报完成。
- 牵头整理自然语言测试指令与演示流程。

**第一个成果：** 能理解“屋顶换蓝色、窗户不动”，遇到对象不明时提出澄清。

## 四、B：视觉感知与结果检查

**研究对象：桌面图像、积木状态、人工变化，以及执行前后的实物证据。**

| 调研技术 | 在本项目中研究什么 |
| --- | --- |
| OpenCV、颜色与几何识别 | 识别颜色、网格占用和位置 |
| 视觉标记与物体跟踪 | 区分同色积木，关联操作前后的对象 |
| 相机标定与坐标映射 | 与 D 对齐图像、桌面和机械臂的位置关系 |
| VLM 与视觉结果判断 | 研究辅助场景理解的方法；固定网格检查优先采用可验证规则 |
| VLA 图像输入与数据采集 | 与 D 确认相机视角、图像格式以及与机器人状态的对应 |

主要负责：

- 向 C 提供当前场景、变化和不确定项。
- 与 D 配合提供 VLA 所需的实时图像；VLA 可能直接使用图像，不必经过网格识别结果才能行动。
- 执行后重新观察，提供“是否到位、颜色是否正确、保护区是否变化”的证据。
- 识别人工操作前后的变化，帮助 C 更新记忆。
- 配合微调数据质量检查与仿真中的感知差异分析。

**第一个成果：** 能识别一块积木的位置，并在搬运后判断它是否到达目标格。

B 提供观察和检查结果；C 结合任务目标形成最终完成结论。观察不清时应返回不确定。

## 五、C：Harness、Memory 与任务管理

**研究对象：长任务的组织、已核验进度、持续约束和异常后的接续。**

| 调研技术 | 在本项目中研究什么 |
| --- | --- |
| Agent 工具调用与 LLM 决策 | 根据任务和反馈选择观察、规划、执行、追问或恢复 |
| 任务状态机与运行循环 | 管理待确认、执行、检查、暂停和完成 |
| Memory：结构化记忆与事件日志 | 保存目标、保护条件、真实进度、人工修改和失败记录 |
| ScenePatch 与逻辑模拟 | 生成必要的局部编辑顺序，检查占用、库存与保护条件 |
| 结果核验与恢复调度 | 使用 B、D 的证据决定继续、重规划、有限重试或请求帮助 |

主要负责：

- 根据用户要求和真实场景，拆出 D 已验证支持的子任务。
- 维护任务表与记忆，向 VLA 提交当前子任务，而不是无差别发送全部历史。
- 在调用前检查任务前提、保护条件和用户确认。
- 组织执行后的观察，只有核验通过才更新完成进度。
- 遇到失败后更新剩余任务，避免丢失已完成成果或盲目重复执行。
- 汇总各模块日志，支持任务回顾和对比实验。

**第一个成果：** 管理一个动作的“下达 → 执行 → 核验 → 完成或暂停”；随后扩展为多个动作。

Memory 第一版只需保存目标、约束、最新场景、已核验进度和相关历史。无需先建设复杂记忆平台。

## 六、D：VLA 与机械臂执行

**研究对象：VLA 模型、真实机器人适配、抓放能力、数据与微调。**

| 调研技术 | 在本项目中研究什么 |
| --- | --- |
| VLA 模型与已有检查点 | 哪些候选模型适合当前机器人与限定任务，是否需要适配或微调 |
| Franka 控制接口、机器人状态与动作表示 | 将模型输入输出与真实设备正确连接 |
| ROS 2 / MoveIt 2 | 根据控制路线决定是否采用，明确与 VLA 的关系 |
| LeRobot、示范采集与 VLA 微调 | 采集对应任务的数据，改善动作可靠性 |
| 物理仿真、Sim-to-Real、可选强化学习 | 后续围绕明确问题开展实验，而非全部作为必做项 |

主要负责：

- 核实实际夹具、相机、计算机、接口和已有程序。
- 尽早验证 VLA 能否完成一种限定抓放；必要时提前做少量微调。
- 向 C 说明可支持的子任务、启动条件、结束方式和已知限制。
- 提供执行状态、停止与查询能力；支持在合适边界切换任务。
- 切换子任务或恢复时，处理未执行的旧动作，避免旧动作队列继续运行。
- 牵头模型微调与物理仿真，其他成员共同承担数据采集和测试。

**第一个成果：** 在指导下，让适配后的 VLA 完成一次真实取放，并返回执行情况。

模型产生动作与控制器执行动作的衔接由 D 负责。VLA 和 MoveIt 不应各自独立同时向机械臂发控制命令，具体路线需要统一设计。

## 七、Harness 怎样帮助记忆和纠错

```text
A：理解完整任务与用户保护要求
                 ↓
C：Harness 读取记忆、选择当前子任务
                 ↓
D：VLA 接收子任务、最新图像与机器人状态
                 ↓
             机械臂执行
                 ↓
B：重新观察，检查目标和保护区域
                 ↓
C：更新记忆，决定继续、调整、重试或求助
                 ↓
A：向用户展示进度与核验结果
```

例如第二块屋顶积木抓取失败：

1. D 返回执行情况，B 观察到积木仍在原位置。
2. C 将第二块保留为未完成，第一块仍为已完成，并记录失败。
3. C 根据新观察判断是否具备重试条件，再调用 D，或通过 A 请求帮助。
4. B 检查重试结果，C 核验通过后才推进任务。

**记忆保存依据，视觉检查发现问题，Harness 组织恢复，VLA 执行新的子任务。** Harness 不会自动补出 VLA 尚未学会的动作能力。

## 八、五阶段分工与验收

前一阶段完成后应已有可独立演示的系统。以下是建议的内部验收安排；前三阶段是课程主要交付路线，第四、第五阶段逐步增强。

### 阶段一：一次动作的完整闭环

**演示任务：** “把指定红色积木移到指定空位。”

| 成员 | 本阶段任务 |
| --- | --- |
| A | 明确文字指令、启动与结果反馈 |
| B | 识别源位置与目标位置，执行后重新观察 |
| C | 最小 Harness：当前任务、状态记录、核验、失败暂停 |
| D | 验证 VLA 真机适配，完成限定抓放与停止反馈 |

**验收：** 输入到真机核验整条流程跑通；在预先记录的若干起始位置重复测试并保留成败记录；积木未到位时不能误报成功；能停止并说明结果。

已有基础抓放程序可以帮助联调，但用其代替 VLA 的演示需明确标注，不能算作 VLA 真机接入完成。阶段一的适配如果需要微调，可以提前开展。

### 阶段二：多步编辑与任务记忆

**演示任务：** “把屋顶三块积木换成蓝色，窗户保持不变。”

| 成员 | 本阶段任务 |
| --- | --- |
| A | 展示修改预览、确认与进度，提供暂停／继续入口 |
| B | 提供布局、材料状态和每步操作后的观察 |
| C | 局部规划、逻辑检查、Memory、已核验进度和任务接续 |
| D | 支持连续子任务、执行状态查询和动作边界暂停 |

**验收：** 能完成多次回收与放置；暂停后重新观察并继续；不重复已完成步骤；窗户保持不变；界面进度与真实结果一致。暂停恢复先限定在同一程序运行期间。

### 阶段三：人工协作与有限异常恢复

**演示任务：** 用户调整窗户，要求保留；随后修改屋顶，在允许的暂停阶段移动一块待取积木，系统重新观察后接续。

| 成员 | 本阶段任务 |
| --- | --- |
| A | 语音与文字入口、上下文澄清、保护标记展示与解除、求助交互 |
| B | 检测人工变化、识别异常并提供可信的新观察 |
| C | 保存人工修改和保护记录，检查旧计划前提，组织受控恢复 |
| D | 验证恢复子任务的可执行性，提供明确的停止、重试和执行反馈 |

**验收：** 人工修改能被记录与保护；至少一种明确异常可实际恢复；缺料、保护冲突或观察不清时正确暂停；恢复保留已有成果；完成不少于 20 条独立指令和 10 次真机局部编辑测试。

此阶段汇总课程能力：三色网格和分区、至少两种初始图案、移动与换色、保护区标记、预览确认／取消、结果核验、停止与人工介入。报告解析正确率、实际编辑成功率、非目标区域误改，以及失败归因。

人工操作回合结束后，B、C 根据可靠变化自动生成保护标记，由 A 显示并提供调整和解除入口；变化不明确时先澄清。最终测试指令与提示词示例分开。

**阶段三完成后，形成可用于课程答辩的完整协作系统。**

### 阶段四：VLA 微调与性能改进

**任务：** 根据前三阶段的实际动作失败，采集数据并改进 VLA。

| 成员 | 本阶段任务 |
| --- | --- |
| A | 整理任务描述和语言标注，维护独立测试指令 |
| B | 检查图像和视觉标注质量，维护统一结果检查 |
| C | 从日志整理失败类型，固定 Harness 配置并汇总比较结果 |
| D | 牵头示范采集、微调、模型接入与动作表现评估 |

**验收：** 训练数据与测试场景分开；在相同 Harness 和相同测试条件下比较模型；报告任务成功、重试、误改和人工介入；依据结果决定是否采用新模型。微调完成本身不等于性能提升。

### 阶段五：仿真与研究扩展

**任务：** 选择一个明确问题，例如位置变化下的抓放表现，使用仿真开展更多测试，并与真机比较。

| 成员 | 本阶段任务 |
| --- | --- |
| A | 组织任务变体、实验展示与结论说明 |
| B | 对齐仿真与真实观察，分析感知差异 |
| C | 复用任务与记忆流程，组织可重复实验 |
| D | 牵头物理仿真、动作验证；按需要探索策略训练与迁移 |

**验收：** 仿真有明确用途和可重复场景；至少一组对应条件接受真机验证；分别报告仿真与真机结果、差异及适用范围。只有实际训练并验证迁移时，才将结果称为仿真训练到真机迁移的成果。

仿真可以按需要提前引入；微调本身属于训练，不要求未来从零训练 VLA，也不要求必做 PPO。

## 十、共同验收与研究结论

每次进入一个阶段，先共同写清测试任务、初始条件、允许的干预与通过条件；验收保留全部尝试，不能只展示成功录像。课程最低测试数量与性能通过门槛是两件事，具体性能门槛在测试前共同确定。

### 分别验证 Harness 与 VLA 的贡献

| 比较内容 | 保持不变的条件 | 主要观察什么 |
| --- | --- | --- |
| 基础编排 → 加入记忆 → 加入核验恢复 | 同一个 VLA、任务条件、执行预算和必要停止／保护机制 | 任务完成、重复操作、误改、恢复和人工介入 |
| 微调前 VLA → 微调后 VLA | 同一个 Harness 与独立测试集 | 动作可靠性与完整任务表现 |

不同 Harness 配置的结果均使用同一套外部验收方式评价；是否利用检查结果自主恢复，才是对应配置之间的差别。若同时改变多项机制，只报告整体改善，不将全部效果归因于 Memory。

原始材料中的“整体重排、差分局部编辑、加入人工保护的局部编辑”策略比较，由 C 牵头、全员配合保留；它用于检验局部编辑与保护的价值，与 VLA 微调对比回答不同问题。

### 四人的协作边界

- **A → C：** 用户要求、澄清与真实确认；**C → A：** 预览、进度与核验结果。
- **B → C：** 新观察、变化和不确定项；**C → B：** 观察请求及关注对象。
- **B ↔ D：** 相机与机器人数据对齐、标定、采集与执行后观察时机。
- **C → D：** 当前子任务与执行／暂停请求；**D → C：** 状态、能力限制与错误反馈。

D 的控制流程结束不等于任务成功；C 必须结合 B 的实物观察判断。结果未知时先查询和观察，不能直接重复发送动作。保护约束由 C 管理、D 的执行边界共同落实，并由 B 核验，不能只依赖一句“窗户不要动”的提示。
