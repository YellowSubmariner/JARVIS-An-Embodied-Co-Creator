**From Digital Intelligence to Physical Autonomy**

**An Embodied Co-Creator Powered by VLA and Harness**

**v2.4.2 Proposal｜工程导论学期项目｜2026-11-01**

> 我们以桌面物理编辑作为第一个应用场景，利用老师提供的 Kinova 7 自由度机械臂，探索“VLA 负责具体行动、Physical Agent Harness 负责持续管理”的具身协作系统。LLM 理解用户意图并参与任务决策，ScenePatch 规划和检查局部修改，Harness 维护记忆、组织核验与恢复，VLA 根据当前子任务、图像与机器人状态生成动作，让智能在真实反馈中接续任务。

## 一、为什么创造 JARVIS：让智能走出屏幕

《钢铁侠》中的 JARVIS 提供了一种令人向往的想象：智能能够理解人的意图，参与设计与创造，并通过现实中的设备帮助人完成工作。

今天，AI 已经进入我们的写作、编程与学习过程。我们开始进一步追问：**能否让智能走出屏幕，拥有一双能够与人类共同创造的手？**

一旦 AI 能够操控物体，问题就发生了变化。语言中的“修改”可以很轻巧，现实中的修改却需要面对位置、材料、动作误差和人的参与。它必须知道自己准备改变什么，也必须知道什么应当被保留。

Project JARVIS 正是对这个问题的一次微缩工程探索。我们计划用一个学期，将老师提供的 Kinova 7 自由度机械臂、摄像头、语言模型、VLA 和语音交互连接起来，完成一个可以与人共同搭建、修改和检查积木场景的实体智能助手。

**项目的技术定位是以 VLA＋Harness 为主线的大模型驱动具身智能。** LLM 理解意图、利用上下文，并参与工具选择与恢复决策；VLA（Vision-Language-Action，视觉—语言—动作模型）根据最新图像、机器人状态与当前子任务生成动作；Harness 管理目标、记忆、进度和执行流程，组织结果核验并决定继续、调整、重试或求助。底层控制器负责将动作落实到真实机械臂。

**How can a Large Language Model evolve from digital reasoning to embodied interaction with the physical world?**

我们将在这条探索路径上加入一个轻量的虚拟工作台，让 JARVIS 先检查局部编辑的布局后果，再依据现实反馈调整下一步。任务接续主要依靠推理、工具调用、记忆和核验；动作能力则需要尽早验证 VLA 的真机适配，必要时在第一阶段就采集少量示范并微调。无需在每次交互时重新训练模型，也不要求从零训练 VLA 或新的管理模型。

**项目要展示的核心，是 AI 在连续人机协作中维护环境状态、理解历史操作、尊重人的修改，并根据真实反馈调整下一步行动。** 一次抓放是它的动作能力，持续完成双方共同提出的任务才是它的具身 Agent 特征。

我们也借用 JARVIS 与 Ultron（奥创）作为两种自主性想象的对照，提出贯穿项目的工程伦理问题：

**When AI gains the ability to change the physical world, how much autonomy should we give it?**

我们的选择是构建一个始终允许人参与、能够解释冲突并接受接管的协作者。它可以自主寻找完成任务的路径，但目标、保护边界和扩大操作范围的决定权属于人。这一选择将落实为系统中的真实机制。

## 二、第一步：一张可以共同创造的桌面

我们将课程中的 PuzzleMate 拼图任务，设计为一间“微缩未来实验室”。

桌面划分为拼图区、备料区和回收区，采用固定网格、三种颜色及少量同尺寸轻质积木。至少准备两种初始图案，以房屋或未来基地的平面布局为主题，预先定义屋顶、窗户、入口等语义区域。

用户说：“JARVIS，醒来。我们一起设计一个未来基地。”

JARVIS 观察桌面材料，将识别到的积木状态映射到 **Virtual Workspace（虚拟工作台）**，展示基于模板的布局草案。用户可以通过语言调整方案；ScenePatch 先检查候选动作引起的状态变化，再通过 Ghost Preview 展示目标布局。确认后，Harness 将计划拆为已经验证支持的子任务，交给 VLA 与机械臂执行。

**Before JARVIS changes the real world, it can first explore possible actions in a virtual one.**

在 JARVIS 真正改变现实之前，它可以先在虚拟世界中探索行动的可能。这延续了电影中辅助设计与实体创造的想象，也为本项目提供一个具体的工程步骤：先在数字布局中预演，再用真实反馈检验。

随后，用户在机械臂暂停期间亲手修改窗户，并告诉它：

> “这是我设计的，保留它。接下来，把屋顶换成蓝色。”

人工操作回合结束后，JARVIS 根据可靠的前后变化自动生成保护标记，展示保护范围并允许用户调整或解除；变化不明确时先澄清。系统记住这次设计选择，再接着完成局部修改。用户也可以说“刚才那块”“先别动”“检查一下再继续”，让共同创作自然地跨越多个回合。

本学期的实体场景限定为单层网格布局。通过语义、交互和可视化营造未来基地的体验，将有限硬件能力集中用于可靠的人机协作。

## 三、真正的挑战：当现实偏离计划

一份计划只有在其依据仍然成立时才值得执行。人可能改变设计，物体可能被移走，机械臂也可能抓空。JARVIS 必须能够区分“我打算完成什么”和“现实中已经发生什么”。

以修改屋顶为例：

1. 用户要求将屋顶换成蓝色，并保留窗户。Agent 查询当前场景与保护记录，调用 ScenePatch 生成计划。
2. 在安全暂停阶段，用户调整部分布局。恢复前的新观察显示，某个待操作物体已不在原位置。
3. Harness 更新环境状态，发现旧计划相关的执行前提失效，阻止继续使用过期计划；执行模块处理尚未执行的旧动作，避免恢复时旧动作队列继续运行。
4. Harness 根据规则和必要的 LLM 决策，选择重新观察、查询修改历史、核对库存或请求澄清。目标仍可实现且动作能力支持时，调用 ScenePatch 生成新的局部方案。
5. 新方案在虚拟工作台中完成逻辑状态模拟与约束检查；涉及实质范围变化时重新确认。Harness 向 VLA 提交新的当前子任务，系统结合执行反馈与新观察核验实际结果，通过后才更新进度。

**下一步由最新观察和工具返回结果共同决定。** 在预先排好动作的一次性流程之外，Agent 能在有限工具集中动态选择查询与恢复路径；执行权限、停止条件和保护检查仍使用明确规则。自主决策与确定性控制各自承担适合的职责。

四项技术特色共同支撑这一能力：

| 技术特色 | 解决的问题 | 职责落点 |
| --- | --- | --- |
| **Physical State Diff** | 当前布局与目标布局有哪些差异？哪些动作可以省去？ | ScenePatch 生成必要的移动、回收与替换清单，尽量减少额外搬运 |
| **Persistent Memory** | 人刚才改了什么？哪些选择需要继续保留？ | Harness 保存场景、任务、已核验进度、人工修改与保护约束 |
| **Constraint-Aware Planning** | 怎样完成目标，同时尊重保护区域、材料与操作边界？ | ScenePatch 在约束内规划并模拟候选状态变化；Harness 在执行前校验并落实边界 |
| **Closed-loop Recovery** | 实际结果是否符合预期？失败后怎样继续？ | Harness 组织新观察、核验与有限恢复，ScenePatch 提供必要的新方案，VLA 执行能力范围内的新子任务 |

状态差分以减少搬运为优化目标，不未经证明宣称全局最优。记忆采用可查询的结构化记录，保护规则不依赖聊天摘要。物体身份通过视觉标记或可靠跟踪维护；无法确认“刚才那块”时，系统高亮候选并询问。

首版聚焦物体位置变化、抓取未成功、目标格被占用和缺料等有限异常。能够可靠识别且处于授权范围内的情况才尝试恢复，观察不清或反复失败时请求接管。

**记忆保存依据，视觉检查发现问题，Harness 组织恢复，VLA 执行新的子任务。** Harness 能改善任务组织，但不能自动补出 VLA 尚未学会的动作能力。

## 四、一个完整的 JARVIS：智能、运行基础与编辑能力

### 4.1 核心模块的关系

| 名称 | 定位 |
| --- | --- |
| **JARVIS** | 整体具身协作者及人机交互形象，集成语言理解、视觉感知、任务管理与实体行动 |
| **LLM** | 理解用户目标、关联上下文，参与工具选择与任务层决策 |
| **Physical Agent Harness** | 从第一阶段加入的运行基础，管理任务生命周期、结构化记忆、已核验进度、工具执行与异常恢复 |
| **ScenePatch** | JARVIS 的局部物理编辑能力，负责受约束的修改计划、候选状态模拟及验收条件 |
| **VLA 与执行适配** | 根据当前子任务、最新图像和机器人状态生成动作，经统一执行接口连接 Kinova 7 自由度机械臂，返回状态与错误反馈 |

**JARVIS 是具身协作者，Harness 管理连续任务，ScenePatch 规划局部修改，VLA 提供具体动作能力。**

Harness 借鉴现有 Agent 工程中的工具循环、外部记忆和进度验证思想，并结合物理任务设计。它属于应用运行框架，不替代机器人底层控制。相关背景可参考 [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) 与 [Effective Harnesses for Long-Running Agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)。

### 4.2 最小可用 Harness

Harness 从第一次真实取放就参与闭环，可以由普通程序、一套小型状态机、一份结构化状态存储、视觉检查和必要的 LLM 决策组成，无需先训练一个新的管理模型。它完成四项职责：

- **维护状态与上下文：** 为 Agent 提供最新场景、相关历史、任务进度和保护要求。
- **推进任务与调用工具：** 接收工具结果，选择观察、查询、规划、澄清和恢复，把完整任务拆成 VLA 已验证支持的子任务，管理暂停与完成状态。
- **检查执行条件：** 校验指令格式、对象、位置、工作空间、计划前提和用户确认，再调度已验证动作。
- **核验与处理异常：** 比较预期和实际结果，记录已验证进度，实施有限重试、暂停、续接或人工接管。

工具采用明确的输入输出，覆盖场景观察、历史查询、库存检查、补丁生成、预览、执行和验收。Harness 向 VLA 提交当前子任务，不无差别发送全部历史；VLA 使用与该子任务对应的最新图像和机器人状态。视觉模块还独立提供布局、人工变化和执行后证据，VLA 使用图像不必以网格识别结果为前提。

执行模块负责模型输出与控制器的衔接，提供状态查询、停止、错误反馈和已知能力限制。视觉模块提供检查证据，Harness 结合任务目标形成完成结论；模型返回、控制流程结束都不能单独代表任务成功。

日志供记忆、界面和实验共同使用。任务时长、调用次数和重试次数设置预算，具体数值通过真机试验确定。

### 4.3 ScenePatch 的输出与虚拟预演

每次编辑生成一份可检查的补丁，包含：**所依据的场景版本、目标状态、执行前提、保护约束、动作顺序、验收条件，以及用户确认的范围。**

例如，换色需要先确定旧积木去向，再安排新积木放置；临时腾挪也不能破坏保护要求。ScenePatch 定义怎样才算修改成功，Harness 使用执行反馈和新观察实施检查并管理任务状态。

Virtual Workspace 复用现有场景表，在状态副本上逐步模拟候选移动、回收与替换，检查中间步骤的目标格占用、材料数量和保护约束。Ghost Preview 展示这些预测结果。它是 ScenePatch 的逻辑检查与展示载体，无需建设独立复杂子系统。

本学期的基础版本属于**逻辑状态模拟**：能够检查布局与动作顺序的一致性，但不能据此证明运动无碰撞、夹持稳定或接触力合理，更不能直接称为完整数字孪生。Harness 分别保存观察状态与预测状态，模拟通过后仍需检查最新实物条件；只有真实执行和核验才能更新已完成进度。

动作发送、控制器返回和实物核验分别记录。完成必须得到结果支持；超时或观察不清标记为待确认，不盲目重发物理动作。保存动作请求编号和执行进度，降低重复提交风险。

系统形成以下虚实结合的闭环：

**Real-world Perception → Task Understanding → Harness / ScenePatch Planning → Logical Preview → VLA Execution → Verification / Memory Update**

即“真实感知 → 理解任务 → Harness 组织局部规划 → 逻辑检查与预览 → VLA 执行子任务 → 实物核验与记忆更新”，必要时进入恢复与重规划。LLM 参与任务层决策，VLA 生成具体动作，机械臂实时控制由底层控制器承担。VLA 与 MoveIt 如同时采用，必须明确各自职责，通过统一控制路径执行，避免两者独立向机械臂发送控制命令。

逻辑预演用于检查布局、库存和保护约束；物理仿真可按实际需要引入，不是基础闭环的前置条件。后续若开展 Sim-to-Real，需要分别记录仿真与真机条件、结果和差异；只有实际训练并验证迁移后，才将结果称为仿真训练到真机迁移的成果。

### 4.5 从 JARVIS 与奥创的想象，走向可执行的边界

我们把“人始终掌握控制权”落实为四条规则：

1. **目标由人提出。** 保护要求持续有效，Agent 不能自行取消；冲突时明确解释，允许用户调整目标或解除保护。
2. **行动范围由人确认。** 预览后支持确认与取消，授权绑定具体计划及恢复范围；实质扩大的计划再次确认。
3. **自主权可以被收回。** 用户能够停止、暂停和接管，人机轮流操作；急停与底层限制独立于模型运行。
4. **完成需要证据。** 系统展示实际变化与检查结果，承认未完成、观察不清和需要帮助的情况。

我们赋予 JARVIS 的，是在明确目标和边界内寻找可行路径的自主性。Human-in-the-loop 因此成为共同创作的方式，也成为系统遇到能力边界时的一条正常路径。

## 五、这一学期，具体完成什么

### 5.1 最低可行版本

前三阶段逐步形成可用于课程答辩的完整系统，应完成一条连续任务：**用户提出局部修改 → Harness 读取场景与历史 → ScenePatch 生成补丁并进行逻辑检查与预览 → 用户确认 → VLA 执行当前子任务 → 重新观察并核验 → 更新记忆并继续；遇到已验证的异常时，在限定范围内恢复，能力不足时明确请求协助。**

同时具备三色网格识别、至少两种初始图案、移动与颜色替换、人工修改记录、保护区域、歧义澄清、停止和接管，以及基本语音和文字交互。必须至少有一种异常可以实际完成受控恢复，不能以所有失败都停机代替闭环能力。

第一版固定相机、单层布局、易抓积木、人机轮流操作。阶段一先跑通文字指令下的单动作闭环，阶段二增加多步编辑与记忆，阶段三完成语音、人工协作与有限恢复。每一阶段保留可独立演示的成果，不必等待所有功能齐备才进行真机联调。

### 5.2 硬件适配路线

硬件信息更新（2026-11-01）：已改用 Kinova 7 自由度机械臂，通过网线连接并通过网页操纵。用户回忆可能是 Gen3，但具体型号尚未核实；网线连接到电脑还是交换机、网页平台名称、API 开放情况、夹爪及腕部视觉配置均待确认。若确认为 Gen3，再评估与固件匹配的 Kortex API。原先针对 FR3／DROID 的模型适配假设需重新验证。

硬件平台为老师提供的 **Kinova 7 自由度机械臂**。首阶段仍需核实实际夹具、相机、计算机、开放接口、已有程序、停止方式、可达范围、重复定位表现和设备时段。相机视角、积木尺寸与网格间距根据真机条件调整，由 B、D 在指导下共同完成标定与数据对齐。

| 适配事项 | 实施路线 |
| --- | --- |
| VLA 模型与已有检查点 | D 牵头比较候选模型的输入、动作表示、设备适配、算力与示范需求，尽早验证一种限定抓放 |
| 图像与机器人状态 | B、D 对齐相机视角、图像格式、状态与时序，明确模型实际可用的输入 |
| 执行与停止接口 | D 统一模型输出到控制器的路径，提供状态查询、动作边界暂停、停止和错误反馈 |
| 现有 SDK、ROS 2 / MoveIt 2 或示教程序 | 根据已有条件复用，辅助标定、控制和联调；明确与 VLA 的职责关系 |
| 动作能力不足 | 先检查设备、数据与适配问题；必要时在阶段一提前采集少量示范并微调 |
| 缺少可调用接口或停止手段 | 尽早与教师确认条件；模拟支持软件联调，真机能力须单独验收 |

已有基础抓放程序可以帮助联调，但若用它替代 VLA 演示，应明确标注，不能计作 VLA 真机接入完成。候选模型和工具的适用性需要实际验证，不预先承诺某个检查点能直接控制当前设备。

### 5.3 前沿技术的取舍

| 技术 | 本项目用途 | 交付定位 |
| --- | --- | --- |
| **LLM 与结构化输出／工具调用** | 理解中文意图、关联历史，参与任务决策与恢复 | 核心；A 负责语言，C 负责任务管理 |
| **VLA** | 根据当前子任务、图像和机器人状态生成动作 | 核心执行路线，阶段一验证真机适配 |
| **Physical Agent Harness 与 Memory** | 任务状态、结构化记忆、已核验进度、接续与恢复 | 从阶段一加入，逐步增强 |
| **OpenCV 与标定视觉** | 网格、颜色、物体身份、人工变化及结果检查 | 核心，必要时使用视觉标记；同时为 VLA 提供图像 |
| **语音识别与合成** | 与 JARVIS 交流、报告关键状态 | 阶段三形成基本语音交互，保留文字与按键入口 |
| **VLM** | 辅助语义理解、交互指代与结果解释 | 按需采用；固定网格检查优先使用可验证规则 |
| **ROS 2 / MoveIt 2** | 驱动与运动规划适配 | 依据实际控制路线采用，D 统一执行路径 |
| **LeRobot 等数据与训练工具** | 示范采集、数据组织、VLA 适配与微调 | 按模型和设备条件选用；微调可提前，阶段四集中改进 |
| **Virtual Workspace / 逻辑 Simulation** | 模拟候选布局，检查占用、库存、保护条件并预览 | 阶段二形成，复用 ScenePatch 与场景表 |
| **物理 Simulation / Sim-to-Real** | 围绕明确问题测试动作，比较仿真与真机 | 阶段五研究扩展，可按需提前；不是基础闭环的前置条件 |
| **PPO 等强化学习方法** | 按需要探索策略训练与迁移 | 可选研究，不列为默认交付 |

可参考 [LeRobot](https://github.com/huggingface/lerobot) 与 [SmolVLA](https://huggingface.co/docs/lerobot/smolvla) 调研数据采集和模型微调路线，但当前不预设最终模型；采用前需要验证硬件适配、示范采集、动作表示和算力条件。[MoveIt 2](https://moveit.picknik.ai/main/index.html) 的接入同样取决于实际驱动、机器人模型及其在统一控制路径中的职责。

可选物理仿真可使用 [MuJoCo](https://mujoco.readthedocs.io/en/stable/overview.html)、[Isaac Sim](https://github.com/isaac-sim/IsaacSim) 或适配条件更好的工具，建立包含机械臂、夹爪、积木和桌面的简单环境。优先复用现成模型，核对几何、关节、控制接口及关键物理参数，逐步比较仿真与真机结果，不开发新的物理引擎。

未来可探索使用 [PPO](https://arxiv.org/abs/1707.06347) 等强化学习方法学习有限动作策略，但仿真训练成功不代表真机可直接使用。策略迁移仍需处理模型误差、感知与控制差异，并通过独立的真机验证。微调本身属于训练，并不要求未来从零训练 VLA，也不要求必做 PPO。

ScenePatch 和 Harness 保留稳定接口，便于后续比较不同 VLA 与微调版本，同时继续使用统一保护规则与验收机制。暂停恢复先限定在同一程序运行期间；选择性撤销、草图到布局和进程重启恢复列为后续探索。

### 5.4 五阶段计划

前三阶段为课程主要交付路线，第四、第五阶段逐步增强。以下是内部验收目标；具体性能门槛应在测试前确定，课程最低测试数量不等于性能通过门槛。

| 阶段 | 演示与主要能力 | 验收重点 |
| --- | --- | --- |
| **一：一次动作的完整闭环** | 文字指定一块红色积木与空位；最小 Harness 管理 VLA 真实取放与视觉核验 | 在预先记录的起始位置重复测试，保留成败记录；未到位不能报成功；支持停止与失败暂停 |
| **二：多步编辑与任务记忆** | 屋顶三块换蓝色、窗户不动；加入 ScenePatch、逻辑预览、确认与已核验进度 | 完成回收与放置；暂停后重新观察并接续；保留保护区与已完成步骤，界面进度对应实物 |
| **三：人工协作与有限异常恢复** | 记录并保护人工修改；语音与上下文澄清；发现待取积木变化后接续 | 至少一种异常实际恢复；缺料、冲突或观察不清时暂停；完成至少 20 条独立指令和 10 次真机局部编辑测试 |
| **四：VLA 微调与性能改进** | 从真实失败整理数据，采集示范、微调并比较模型 | 训练与测试分开；固定 Harness 和测试条件；报告成功、重试、误改及人工介入，依据结果决定是否采用新模型 |
| **五：仿真与研究扩展** | 围绕位置变化下的抓放等明确问题，建立可重复实验 | 至少一组对应条件接受真机验证，分别报告仿真与真机结果、差异和适用范围 |

阶段一如需微调可提前开展，物理仿真也可按需要提前辅助定位问题。阶段四、五是集中改进与研究安排，不应阻止尽早完成真机闭环。四人共同安排设备时段与周计划，后期留足故障修复、完整测试和答辩排练时间。

### 5.5 ABCD 协作

| 成员 | 主责 | 主要衔接 |
| --- | --- | --- |
| **A** | 语言理解与人机交互 | 把任务、澄清和真实用户确认交给 C，展示预览、进度与核验结果 |
| **B** | 视觉感知与结果检查 | 向 C 提供场景、变化和不确定项；与 D 对齐图像、状态和观察时机 |
| **C** | Harness、Memory 与任务管理 | 管理目标、保护、规划与已核验进度，向 D 下达当前子任务并组织恢复 |
| **D** | VLA 与机械臂执行 | 负责模型与设备适配、控制接口、执行反馈，牵头数据采集、微调与仿真 |

优先由 A、C 接通任务理解与管理，B、D 接通感知与 VLA 真机动作，再由四人共同完成一次动作的完整闭环。C 主责管理流程，D 主责动作能力，全局联调与测试由全员参与；详细分工见 [ABCD 研究分工与协作 Version 2](ABCD研究分工与协作_Version2.md)。

## 六、连续 Demo：让评委看见一个正在协作的 JARVIS

答辩围绕同一个未来基地展开，用几分钟完成“理解—共创—记忆—变化—恢复—核验”的连续体验，时长按机械臂实测速度调整。

**唤醒。** 用户说：“JARVIS，检查工作台。我们一起搭建一个未来基地。”屏幕显示真实桌面、识别对象和材料状态。语音唤醒是目标体验，现场嘈杂时可使用按键入口。

**共创。** JARVIS 将真实桌面映射到虚拟工作台，在状态副本上检查候选修改，再展示 Ghost Preview，标出待放置与待改变的位置。用户修改方案并确认，Harness 组织 VLA 逐个执行子任务，每步核验后更新进度。基础作品可预先搭好，将现场时间集中在最有意义的几次编辑。

**记住人的设计。** 机械臂暂停且允许人工操作后，用户亲手调整窗户：“保留我刚才改好的部分。”人工回合结束，系统高亮可靠变化、自动生成保护标记并保存；界面支持调整和解除，变化不明确时先澄清。

**继续修改。** 用户说：“现在把屋顶换成蓝色。”JARVIS 查询历史、检查库存与位置，展示局部修改，保留窗户和其他不需要改变的区域。

**面对意外。** 在允许的暂停阶段，将一块待取积木移到另一已标定位置。JARVIS 在执行前发现旧位置失效，重新观察与定位；更新虚拟布局，在已确认范围内重新规划和检查，然后继续执行并核验结果。异常类型预先设计，检测与恢复依据现场数据运行，不播放预设的成功回应。

**完成与回顾。** 屏幕呈现实际完成情况、保护区域及修改记录。时间充足时加入 JARVIS Briefing，用本次日志生成简短语音汇报；涉及未记录的数据交由团队回答。

控制面板聚焦四件事：**真实环境、目标预览、动作进度、结果验证。** 深色界面、物体轮廓和状态动画营造未来实验室氛围，每个提示都对应可检查的信息。Ghost Preview 是状态预览，不宣称具有未经验证的物理仿真能力。

Mission Resume 复用任务状态，先实现同一程序运行期间、已验证动作边界上的暂停、重新观察与续接。切换子任务或恢复前处理未执行的旧动作；结果未知时先查询与观察，避免重复发送物理动作。人工进入工作区以机械臂停止且允许操作为前提；语音暂停不能替代独立急停。Briefing 期间关闭机械动作权限，将展示工作量限制在现有能力之内。

## 七、工程验证与交付：让能力有真实证据

### 7.1 对齐 PuzzleMate 验收

| 原有要求 | JARVIS 对应实现 |
| --- | --- |
| 固定网格、三色同尺寸轻质积木、拼图/备料/回收分区；至少两种初始图案 | 微缩工作台与语义区域模板 |
| 积木编号、颜色、网格、占用状态，叠加显示识别结果 | 场景状态表与实时面板 |
| 自然语言转结构化指令，至少支持移动与换色 | LLM Tool Use 与 ScenePatch 请求；不直接执行模型生成的代码 |
| 格式、对象和位置合法性检查；目标缺失、指代不清时澄清 | Harness 校验与 Agent 查询、澄清工具 |
| 局部修改、界面标注保护区、预览、确认与取消 | 约束规划、虚拟状态检查与 Ghost Preview |
| 明确回收和放置顺序，阻止目标占用及保护冲突 | 补丁动作序列与执行前检查 |
| 标定后抓取、搬运、放置、回等待位；人机轮流操作 | 经真机验证的 VLA／执行适配与人工协作回合 |
| 执行后核对；停止、失败提示、人工接管 | 视觉验收与异常处理 |
| 至少 20 条测试指令、10 次真机局部编辑 | 独立测试集与完整运行记录；测试指令与提示示例分离 |
| 分别报告解析正确率、实际编辑成功率、非目标误改 | 分层指标及语言、识别、校验、执行错误日志 |
| 截图 3 的人工修改历史、上下文理解与编辑策略比较 | 记录人工变化并自动生成保护标记，支持调整、解除和策略对照实验 |

原始材料第三张截图的栏目归属不明；团队在当前计划中纳入这两项内容，不据此推断其在课程原文中属于必做或选做。VLA＋Harness 是团队技术路线，原始任务并未指定这些模块或要求采用 VLA。

### 7.2 一个值得回答的问题

**在相同 VLA 下，加入任务记忆与核验恢复，能否改善多步编辑、人工干预和任务中断后的表现？**

分别验证任务管理、动作能力和局部编辑策略的贡献：

| 比较内容 | 保持不变的条件 | 回答的问题 |
| --- | --- | --- |
| **基础编排 → 加入记忆 → 加入核验恢复** | 同一个 VLA、任务条件、执行预算与必要停止／保护机制 | Harness 是否改善完成率、重复操作、误改、恢复和人工介入 |
| **微调前 VLA → 微调后 VLA** | 同一个 Harness、独立测试集与测试条件 | 动作可靠性及完整任务表现是否改善 |
| **整体重排 → 差分局部编辑 → 加入人工保护的局部编辑** | 相同大模型、VLA、视觉与机械臂接口，以及可比任务条件 | 局部编辑与保护是否减少额外搬动、非目标变化和用户再次纠正 |

不同 Harness 配置均使用同一套外部验收方式评价；是否利用检查结果自主恢复，才是对应配置之间的差别。必要停止与保护机制始终保留。微调数据与测试场景分开，完成微调本身不代表性能提升。若同时改变多项机制，只报告系统级改善，不将全部效果归因于 Memory 或单一模块。

重点记录任务完成率、非目标区域误改、额外搬运、异常恢复成功情况、人工接管与再次纠正次数，同时报告解析正确率和耗时。完成要求目标与保护约束同时满足；额外搬运相对预定义的可行参考计划计数。主动人工设计与为弥补系统失败而介入分别记录。

测试覆盖移动、换色、区域保护、目标缺失和含糊表达，使用不同于演示台词的指令。异常和初始条件保持可比，保留失败案例；课程最低数量用于验收，多组实验需要相匹配的任务和重复试验，样本有限时如实报告探索性结果。

虚拟工作台沿用这些用例，检查候选序列是否违反占用、库存或保护规则，并对照预测状态与实际结果。逻辑模拟、可选物理仿真和真机结果分别记录，不能用模拟成功替代真实任务完成率。

### 7.3 最终交付与项目价值

最终交付一套可运行的真机系统、一段连续人机协作演示、一份验收与实验报告、一个带部署和硬件说明的代码仓库，以及清晰的团队分工和个人贡献记录。

测试配置、日志与失败案例可作为小型开放案例集发布，逐步积累为 ScenePatch-Bench；不要求本学期另建大型评测平台。注明依赖、许可证与复现条件，区分社区成果和团队自行实现。

工程价值体现为完整系统能够运行；技术价值体现为状态记忆、受约束局部编辑与恢复得到验证；想象价值体现为一次可体验的人与具身 AI 共同创造。简历使用本人实际负责的模块与真实测量结果，后续研究从这些证据和仍未解决的问题继续展开。

## 八、当智能真正拥有行动能力

今天，我们交给 JARVIS 的是一张桌面。它需要听懂人的要求，理解正在形成的作品，记住一次设计选择，并用机械臂完成下一步。

它也拥有这张桌面的数字映射：可以先在虚拟空间中检查一种修改，再通过实体动作和新的观察检验它。数字推理、虚拟预演与物理反馈由此连接起来，使“大模型理解世界”逐步走向“具身智能与世界交互”。

未来，同样的思想或许能进入工业机器人的备料与返工、智能制造中的柔性换单，以及未来实验室的辅助操作。人提出目标、判断价值、处理新的情况；智能体理解当前环境，在明确边界内接续任务，并将行动结果交还给人检查。

更远的愿景可以延伸到高精度医疗机器人与 AI 辅助手术。那需要独立的专业感知、精密控制、医学研究、严格验证和安全保障，不能从桌面原型直接推导出应用能力。它值得被保留为长期问题：当行动越来越精细、后果越来越重要时，我们怎样让智能既有能力，也懂得何时等待人的决定？

JARVIS 与奥创的对照最终指向我们自己的设计选择。智能体的价值不应只由“它能自主做多少事”衡量，也应包括它能否尊重人的成果、承认不确定性、接受纠正，并在需要时把控制权交还给人。

当 AI 真正能够理解并作用于物理世界，我们与它的关系，或许会从屏幕前的一问一答，延伸为共同观察、讨论、尝试和创造。这个未来可以从一个很小的动作开始，但每个动作背后，都应有目标、边界与对结果的认真核验。

**How can intelligence safely act upon the physical world?**

我们用一个学期、一张桌面和一台机械臂，尝试给出第一个可以被看见、被操作、被检验的回答。

**Project JARVIS — From Digital Intelligence to Physical Autonomy.**

**An Embodied Co-Creator Powered by VLA and Harness.**

**我们不是在教机器人移动积木，而是在探索智能如何安全地作用于现实世界。**

*Today, we teach AI to move a block. Tomorrow, we may teach it to understand how to change the world.*

**今天，我们尝试让 AI 移动一块积木；未来，我们希望它能够理解如何改变世界。**
